# Litterly

A small iPhone and Android app for cat and dog breeders. The first version supports account creation and login with an eight-digit email code, plus registering and viewing born litters.

The interface is Swedish. All product text lives in `apps/mobile/src/locales/sv.json`, using i18next and react-i18next. Add another JSON resource and register it in `src/lib/i18n.ts` to introduce a language later.

## Architecture

```text
Expo / React Native app
  |-- Authentication ----------------> Supabase Auth
  |-- Bearer-token API requests ------> Fastify API
                                         |-- User-scoped queries --> Supabase Postgres
```

- `apps/mobile`: Expo SDK 58, TypeScript, Expo Router, and Swedish translations.
- `apps/api`: a small Fastify TypeScript API. Verifies access tokens with Supabase Auth, validates requests, derives ownership from the authenticated user, and accesses the database with that user's token.
- `supabase/migrations`: constraints, explicit grants, and owner-only Row Level Security.
- `supabase/templates`: code-based email templates for first-time signup and returning sign-in.

Normal app/API operations use only publishable keys. The API does **not** bypass RLS. No service-role key is needed by the app or API.

The app sends all litter operations through the API. The Supabase Data API remains reachable under RLS, so fundamental data rules also live in database constraints. This is defense in depth, not a backend-only database connection. If a later workflow must only be callable by our server, introduce an explicitly restricted database interface for that operation.

## Requirements

- Node.js 22.13+ and npm. Node 24 LTS is recommended.
- For native builds: Xcode on macOS for iOS, or Android Studio and an Android SDK for Android. Alternatively, configure Expo's cloud builds later.

The repository's Supabase CLI is linked to the dedicated hosted Litterly project `blnxhqyweeutxqmggoph`. The litter-table migration has been applied there. This project uses hosted Supabase only; no local Supabase database, Auth server, Studio, or Mailpit is needed. The unrelated project attached to some editor tools has not been modified.

## Development Setup

Run from the repository root:

```sh
npm install
```

The Supabase CLI is included to manage migrations against the linked hosted project. It is not used to start a local Supabase stack. The CLI is pinned to the tested v2 release; targeted dependency overrides patch its archive library and tooling's minimatch dependency.

Create `apps/api/.env` and `apps/mobile/.env` using their `.env.example` files. These files are ignored by Git. Set the Supabase URL to `https://blnxhqyweeutxqmggoph.supabase.co` and use that project's publishable key. The Fastify API runs locally at `http://localhost:3001` during development:

```dotenv
# apps/api/.env
SUPABASE_URL=https://blnxhqyweeutxqmggoph.supabase.co
SUPABASE_PUBLISHABLE_KEY=your-project-publishable-key
HOST=0.0.0.0
PORT=3001
CORS_ORIGINS=http://localhost:8082
```

```dotenv
# apps/mobile/.env
EXPO_PUBLIC_SUPABASE_URL=https://blnxhqyweeutxqmggoph.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-project-publishable-key
EXPO_PUBLIC_API_URL=http://localhost:3001
```

Never put a secret or service-role key in an `EXPO_PUBLIC_` variable. These values are bundled into the client. The publishable key is intended for client use; RLS enforces data access.

Start the API and the app in separate terminals:

```sh
npm run api
```

```sh
npm run web
```

Open `http://localhost:8082`. The web target is a convenient first way to test the same app code while native builds are being set up. Native entry point:

```sh
npm run mobile
```

### Test the First Flow

1. Enter an email and choose **Skicka inloggningskod**. A new email automatically creates an account.
2. Enter the eight-digit code sent to your inbox and choose **Logga in**.
3. Choose **Registrera kull**, select **Katt** or **Hund**, and enter a name, birth date (`YYYY-MM-DD`), and animal count (1–30).
4. Save the litter and view its details. Return to **Mina kullar** to see the saved record.
5. Log out and sign in again using the same email and a fresh code.

Codes are sent by the hosted Supabase project's configured SMTP provider. There are no pre-created accounts or demo records. Templates are in `supabase/templates/magic_link.html` and `supabase/templates/confirmation.html`; both use `{{ .Token }}`.

### iPhone and Android

From `apps/mobile`, run `npx expo run:ios` or `npx expo run:android` after installing the native toolchains. Native directories are generated by Expo and are not hand-maintained. Email-code sign-in works without a deep-link callback.

For an Android emulator, use `http://10.0.2.2:3001` for the API. The hosted Supabase URL remains unchanged. The iOS simulator can use `http://localhost:3001` for the API.

For a physical device, set `EXPO_PUBLIC_API_URL` to your computer's LAN IP and keep the device on the same network, or deploy the API and use its HTTPS URL. The hosted Supabase URL remains unchanged. Restart Metro after editing environment variables.

Expo Go can preview screens and test email-code login using the hosted Supabase project.

## API

| Method | Path | Authentication | Result |
| --- | --- | --- | --- |
| GET | `/health` | None | `{ "status": "ok" }` |
| GET | `/litters` | Bearer access token | `{ "litters": [...] }` |
| POST | `/litters` | Bearer access token | `201 { "litter": ... }` |
| GET | `/litters/:id` | Bearer access token | `{ "litter": ... }` |

Registration accepts `species` (`cat` / `dog`), `name`, `born_on`, `count`, and optional `mother_name`, `father_name`, and `notes`. Unknown fields, including a client-provided `owner_id`, are rejected. Dates must be real, positive-year calendar dates on or before today in UTC. Parent names are plain text, not separate animal records.

List results are limited to the 100 most recently born litters. Errors use `{ "error": { "code": "..." } }`; the mobile app translates error codes, not raw server messages. An unowned litter returns the same 404 as a missing litter. UPDATE and DELETE are not granted in this milestone.

CORS only permits the configured browser origins. Native apps do not depend on CORS for security. Rate limits are per API process/IP; configure trusted proxies and shared limits deliberately when deploying multiple instances. HTTPS is required for production API and Auth URLs.

## Verification

```sh
npm run typecheck
npm run lint
npm test
npm run build -w @litterly/api
```

`npm test` runs API unit tests and mobile form-validation tests without making requests to Supabase or changing hosted data.

Check Expo compatibility and export all three JavaScript targets from `apps/mobile`:

```sh
npx expo-doctor
npx expo export --platform all
```

An export validates JavaScript bundling; it is not an installed iOS/Android binary or an end-to-end UI test. Device navigation, keyboard behavior, deep-link delivery, and visual layout still need manual device testing before release.

## Hosted Supabase Project

1. The dedicated project `blnxhqyweeutxqmggoph` is linked to this repo and the checked-in litter migration has been applied.
2. The **Magic Link** and **Confirm signup** templates should both use the eight-digit `{{ .Token }}` value. The template files are in `supabase/templates/`. Set the hosted OTP length to 8 and configure SMTP for delivery.
3. To apply future migrations, verify that the CLI is linked to this project with `npx supabase projects list`, review pending changes with `npx supabase db push --linked --dry-run`, then apply with `npx supabase db push --linked`.
4. Before sharing the app, deploy `apps/api` as a Node service (`npm run build -w @litterly/api`, then its `start` script), update `EXPO_PUBLIC_API_URL` to its HTTPS URL, and rebuild the mobile app. Register app identifiers with your Apple/Google developer accounts before store publishing.

Photos, individual kittens/puppies, editing, planned litters, pedigrees, shared breeder access, and store distribution are intentionally outside this first milestone.
